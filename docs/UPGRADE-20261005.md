## 第一轮：GitOps 与管理端点

原 Argo Healthy/sync Unknown，ComparisonError 指向旧笔记本代理 192.168.1.106:10808。笔记本现场 IP 已变化。repo-server 通过现有云代理 10.0.0.1:3128 执行 git ls-remote，真实 main=1498ebcd。

首次切换至云代理后，复验发生超时/502，故不能把一次 ls-remote 成功当作链路稳定。随后从 repo-server 显式 `git -c http.proxy=http://192.168.1.236:10808 ls-remote` 成功读取新提交，专属 proxy 切换到该现有笔记本入口，Argo 开始同步。此入口依赖笔记本在线和 DHCP 地址，稳定出口仍是后续缺口。仅 patch argocd/petclinic-repository Secret 的 proxy，未改全局代理/DNS/宿主网络/认证/其他 Application。首份备份仅在服务器 `/opt/petclinic-observability/backup/petclinic-repository-before-20261005.json`，0600，不进 Git。hard refresh 后 Synced/Healthy、无 ComparisonError。

生产环境通过 Deployment env 限制 Web 端点为 health/info/prometheus/metrics，关闭无接收端 OTLP metrics，保留 traces。复用已验证双架构镜像 0.9.0-ci-101，只更新运行配置；无需重编译相同代码或拉取外部镜像。Git→Argo 发布，不直接改线上 Deployment。

回退：Git revert 配置提交，由 Argo 收敛，不用 rollout undo 对抗 selfHeal。仓库代理仅从服务器备份恢复 proxy 字段，不覆写后续其他字段；失效旧代理不可直接恢复，须先验证可达性。
