# Petclinic 0.9 平台集成与数据观测

本版把 Petclinic 的运行数据和已安装平台软件放入同一个可验证的工作台。指标通过 Micrometer / Prometheus 进入 Grafana；ECS 请求日志和数据库聚合快照通过 Filebeat 进入 Elasticsearch / Kibana，并继续通过 Alloy / Loki 进入 Grafana；OTLP 请求追踪通过已有 OpenTelemetry Collector 进入 Jaeger。

平台页面 `/platform` 提供 Grafana、Kibana、Jaeger 入口，以及全平台部署 / 工具的真实采集状态。当前有 69 个 Kubernetes 工作负载与 5 个独立 OSINT 运行环境，不能把工作负载数量当成独立产品数量。每分钟更新外部 ConfigMap；超过三分钟未更新则显示数据过期，指标为 NaN。业务数量在三个副本上是相同数据库的读数，Grafana 使用 max 聚合，不能 sum 重复计数。数据库不可读时同样为 NaN，并有单独可用性指标。

发布成功后写入 Kafka 的 `petclinic-release-v09` 事件流，保留版本、源码 SHA、构建号和时间。Jenkins 归档平台集成 JSON 结果和 JUnit 报告。

Jenkins 新增 SonarQube 分析与质量门禁、GitLab 私有源码镜像和 Harbor 双架构镜像副本。既有 GitHub、Jenkins、Maven、Docker buildx、本地 Registry、ArgoCD、Kubernetes、PostgreSQL 链路保留。Harbor 保留原 OCI index digest 并请求 Trivy 扫描；扫描已请求与扫描完成分别记录，不能据请求返回成功宣称扫描通过。GitLab 镜像不使用强制推送；源代码 SHA 必须匹配。镜像附带轻量 GitLab Runner 审计任务，其结果需要单独验收。

OSINT 不自动查询第三方目标，只读取运行环境安装检查、工具平台健康与任务状态数量。目标、邮箱、用户名、报告内容、API Key 不传入 Petclinic、Kibana 或 Grafana。HTTP 请求日志只记录模板路由、方法、状态、耗时及 Trace ID，不记录查询参数、请求正文或业务身份。

暂停的 Airflow、MinIO、Flink、Spark、Zabbix 等软件仍显示已停用，其他未接入 Petclinic 业务链路的软件明确标记待接入。平台部署健康监测全覆盖不代表每个产品已经成为 Petclinic 的业务依赖。恢复大数据和调度服务需要单独评估资源；当前阿里云节点 NotReady，生产副本继续固定在 devops。

## 运维与回退

平台采集器为服务器 systemd timer `petclinic-platform-snapshot.timer`，代码安装在 `/opt/petclinic-observability/`，输出为 namespace petclinic 中的外部 ConfigMap `petclinic-platform-snapshot`。应用只读该文件，不持有集群 API 凭据。现有 Filebeat 增加仅匹配 Petclinic JSON 容器日志的解析器，其他输入配置保留；OTel traces 增加 Jaeger 导出器，原 metrics / logs 处理链路保留。两份原始 ConfigMap 保存在服务器该目录的 `backup/`，不包含业务数据。

Harbor 的已有 Docker 出站代理无法处理内部域名，镜像归档使用节点内部 Registry HTTP API 直接流式复制，不修改 Docker 全局代理，不通过 Docker Hub 下载。增加独立 Ingress `petclinic-harbor-alias` 为已有域名提供入口，保留原 Harbor Ingress。服务器 hosts 新增 core.harbor.domain 指向本机，仅用于现有 Harbor 域名访问。

回退应用使用普通 Git revert / promotion；保留数据库。停止采集 timer 可停止平台元数据更新；应用会明确显示过期。恢复服务器 backup 中的两个 ConfigMap 并重启相应采集器，可撤销 JSON 解析与追踪转发。新建 GitLab 私有镜像、Harbor 归档、Kibana Data View 是本版独立资源，保留或清理需根据实际使用决定，不删除既有平台数据。

## 验证

本地完整原有测试通过（79 项，0 失败/错误，2 项依赖 Docker 的测试跳过），新增三个观测测试通过，Maven 打包和 Checkstyle 通过。桌面和手机独立预览的首页、系统状态及平台页均 HTTP 200，无横向溢出与脚本错误。生产发布、SonarQube、GitLab、Harbor、Prometheus、Elasticsearch、Loki、Jaeger 与浏览器的最终结果在完成后补充，当前不能将预览结果当作上线结果。

官方参考：[Spring Boot Tracing](https://docs.spring.io/spring-boot/reference/actuator/tracing.html)、[Spring Boot ECS Logging](https://docs.spring.io/spring-boot/reference/features/logging.html)、[Filebeat filestream](https://www.elastic.co/docs/reference/beats/filebeat/filebeat-input-filestream)、[SonarScanner for Maven](https://docs.sonarsource.com/sonarqube-server/analyzing-source-code/scanners/sonarscanner-for-maven)。

首次 #88 构建期间共享服务器出现严重资源争用（负载约 96，vmstat 显示频繁换页）。为补齐浏览器 CSS 发行版本缓存并控制资源，终止了本次 Maven 进程；#88 记录仍为 FAILURE，不作为验收成功。新的 Maven / 测试 JVM 限制为 384 MiB 堆和 2 个可见 CPU，Spring 测试上下文缓存最多 4 个，保留 JaCoCo agent、全部测试和质量门禁。

发现本地节点旧三个副本与新三个启动副本并行时出现换页与 API 响应延迟。滚动更新改为 `maxSurge: 1`、`maxUnavailable: 0`，保持三个服务副本，仅逐个启动替换，降低共享节点峰值负载。
