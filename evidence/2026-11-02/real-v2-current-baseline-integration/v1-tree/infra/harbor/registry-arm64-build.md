# Native ARM64 registry recovery · 2026-10-23

Both existing registry containers crashed in Go netpoll under the experimental QEMU 10.2.3 interpreter after guest reboot. The global interpreter and boot override were rolled back using the saved original registration and verified untouched Ubuntu binary. No claim is made that this emulator is safe for every existing AMD64 service. Do not re-enable that global override based only on a package installation smoke test.

The replacement serves the existing distribution v2 storage and configuration using the official stable Harbor distribution fork `v2.8.3-harbor.1`, commit recorded in `registry-arm64-lock.json`. It is not a byte-for-byte recompilation of the prior AMD64 binary. No storage format migration, garbage collection or persistent data deletion was performed. The existing native registryctl sidecar is retained.

Compile the frozen source with checksum-verified Go 1.25.3, GOOS=linux, GOARCH=arm64, CGO_ENABLED=0, `-mod=readonly -p 2 -tags 'include_oss include_gcs'`; Go verifies dependencies against go.sum. Build `Dockerfile.registry-arm64` offline with the resulting `registry` binary and the existing Linux CA bundle. Import the immutable ARM64 OCI manifest into containerd before the registry itself can start, then publish the same digest to the recovered local registry. Preserve containerd's original imported image-name alias as well as the immutable alias to avoid a stale CRI image-ID reference. The pinned image is about 13MiB compressed.

`registry-arm64-patch.json` is a strategic patch for container **name** registry, applicable to existing ns-devops/local-registry and harbor/harbor-registry Deployments. Preserve their complete original manifests, mounts, Secrets, security context and replicas. Readiness must pass and source/layers must still be retrievable. The complete subsequent Jenkins push, Harbor scan and deployment validate actual registry use; readiness alone does not complete acceptance. Keep these image overrides in later Helm updates.

Rollback uses each saved original Deployment and retained original image, with the original binfmt interpreter restored. Never delete the registry storage or run GC as a recovery shortcut. This is a compatibility repair, not a claim that all Harbor/registry dependency vulnerabilities are zero. Fresh builds of later AMD64 libc packages under the original QEMU remain a separate compatibility limitation; cached multiarchitecture publication must be reported honestly.
